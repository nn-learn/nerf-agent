# Agent V5：可信记忆治理

Agent V5 将现有“可提取、可合并、可召回”的 Memory 升级为可追溯、可纠正、可遗忘且不能越权影响心理支持决策的可信记忆系统。V5 不替换现有 Ollama 提取器或 BGE 候选召回，而是在写入、更新、召回和删除路径增加 host-owned 治理契约。

## V5.0：Memory Ledger

V5.0 已为原子记忆增加以下持久化字段：

- `source_type`：区分用户陈述、用户编辑、模型提取、外部工具、视觉观察和旧数据；
- `sensitivity`：区分普通、个人、健康敏感和危机敏感信息；
- `allowed_uses`：显式限定个性化、回答上下文、安全支持或聚合分析用途；
- `observed_at_ms`：记录系统何时观察到该主张；
- `valid_from_ms / valid_to_ms`：记录主张在现实世界中的有效区间；
- `derived_from_memory_ids`：记录摘要、归纳或其他派生记忆的来源链。

旧数据库会以 `LEGACY / GENERAL` 和最小兼容用途完成在线迁移。新派生记忆的父节点必须存在且属于同一用户，悬空引用和跨用户 lineage 会 fail-closed。`valid_to_ms` 到期的事实不再参与当前召回，但仍保留在可审计历史中；数据保留期限继续由 `expires_at_ms` 独立控制。用户编辑会被明确标记为 `USER_EDIT`，并刷新观测时间，而不是伪装成模型原始提取。

## V5.1：撤回与可验证级联遗忘

V5.1 将 lineage 从审计字段落实为生命周期约束：撤回一条源记忆时，所有直接和间接派生记忆同步进入 `REVOKED`，不再参与召回，但仍保留来源链供审计；物理删除时，在单一事务内递归清除源记忆、派生原子记忆、episode summary、profile evidence、retrieval 和 shadow ranking。

删除完成后再次查询目标集合，任何残留都会使事务失败。系统只持久化内容无关的 `MemoryDeletionReceipt`：根记忆 ID 的哈希、删除总数、派生删除数、完成时间和验证摘要，不保存被删除原文。删除和撤回均按用户隔离，错误租户不能探测或操作其他用户记忆。

## V5.2：Memory Use Policy

V5.2 在词法/BGE 候选召回与 prompt 注入之间加入 host-owned `MemoryUsePolicy`。策略按 `allowed_uses`、来源类型、敏感等级、用户是否主动重提、当前风险和本轮危机证据作最终授权；向量相似度和模型不能绕过该层。

健康敏感记忆只有在用户主动且明确重提相关敏感主题时才能进入普通回答上下文，禁止数字人主动唤起。历史危机记忆不能建立当前风险；只有当前风险控制面已独立判定为 `RED/EMERGENCY`，且当前轮再次提供危机证据时，历史危机记忆才能以 `SAFETY_SUPPORT` 用途进入上下文。外部工具和视觉观察不能用于个性化推断。注入模型的证据包显式携带来源类型、敏感等级和有效时间。

## V5.3：用户记忆控制

V5.3 在原有查看、更正、确认和兼容删除接口上增加四项用户控制：

- `POST .../memories/{memory_id}/control`：暂停或恢复记忆；暂停沿派生 lineage 传播，保留审计但立即退出召回；
- `PUT .../memories/{memory_id}/uses`：用户以枚举白名单修改允许用途，空集合或重复用途 fail-closed；
- `GET .../memories/export`：导出用户可见的原子记忆、状态、provenance、用途和时间字段，不暴露内部 user ID、profile hash 或系统审计标识；
- `POST .../memories/{memory_id}/forget`：级联物理删除并返回 V5.1 内容无关验证凭证。

原有 `DELETE` 保持 `204` 兼容语义，避免破坏既有客户端。恢复暂停记忆时，如果同一 subject 已存在更新的 ACTIVE 记忆，系统拒绝恢复并要求先解决冲突，防止旧偏好静默覆盖新事实。

## 后续阶段

- V5.4：过时记忆、反事实收益、跨用户泄漏和删除完整性评测；
- V5.5：仅在多跳时间/关系查询确有收益时引入轻量图记忆。

## 边界

Memory 只能提供带来源的候选背景，不能单独完成诊断、当前风险判断、Care Loop 目标确认或干预授权。工程测试证明数据契约和迁移行为，不证明临床有效性或生产合规。
